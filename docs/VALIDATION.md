# 验证方法与边界

本项目的自动检查用于证明源码能够构建、数据处理符合约定、基础界面能够运行。它们不能证明国行一代已经与 iPhone 互通。

当前验收版本为 **0.4.0（构建 5，报告 schema 5）**。本版保留持续接收、传输身份及密钥协商，在认证成功后移交当前业务会话；用户主动继续时发送开始设置和状态查询，记录真实首次设置状态。账号绑定与完整首次设置仍未实现。下述回归定义该版本的验收场景；**执行结果以本次提交的 CI 记录为准，新增用例存在不等于已经执行通过**。

## 自动检查

工作流位于 `.github/workflows/ios.yml`，每次运行的实际状态和日志见 [GitHub Actions](https://github.com/apple1day/mywatch-apple/actions)。

| 检查 | 覆盖范围 |
| --- | --- |
| 工程生成与配置 | XcodeGen、Info.plist 蓝牙用途说明、目标系统、测试 target 与签名配置引用 |
| 模型测试 | 名称候选的边界、标准值合法性、会话匿名化、报告里 GATT 与原厂绑定的区分 |
| 协议编解码 | APK 请求向量、独立 CRC 校验向量、通知拆分／粘连、分片与序号、两种 CRC 字节序；有界重同步与无关消息隔离；目标能力的严格 CRC / protobuf 校验及回显识别；业务完整加密载荷的封装与重组 |
| 通道识别 | 必须同时匹配命令服务、写入方向和通知属性；缺失、错误服务与重复端点不能开启查询 |
| 模拟器 UI | 原生 App 启动、首页、连接范围说明、扫描与导出入口；不执行实际蓝牙连接 |
| 模拟器截图 | 保存真实模拟器的首页截图用于布局复核 |
| 无签名设备构建 | 验证 iPhone/iPad 目标编译与链接；不使用个人证书 |

模拟器检查不把虚构设备、虚构电量或伪造 GATT 成功作为测试数据展示给用户。App 的蓝牙管理器在用户主动扫描时才初始化。

## 0.4.0 新增检查

测试入口包括 `OppoBusinessSessionTests`、`OppoBusinessWireTests`、`OppoSetupTests`、`OppoInitialSetupIntegrationTests`，以及扩展后的 `OppoAuthenticationTests`、模型和界面测试。它们验证以下实现边界，不使用虚构成功状态代替手表结果。

| 检查 | 预期 |
| --- | --- |
| 身份到业务的移交 | 身份全部成功且最终所需写入确认后才能取得会话；一次可取；失败、超时或取消不能泄露可用上下文；移交后仍由当前连接持有 |
| 实际加密模式 | 明文会话保持载荷；加密会话采用完整 SID/CID/protobuf 的 AES 封装；模式不符被拒绝，不能静默降级；失效后不能再次封装或解密 |
| 独立业务向量 | 固定 `11/7`、空 `11/11` 与独立 AES/CRC 合成向量核对；先整体加密再分片，每片重复 `0x40`，FSN 可回绕 |
| 加密重组与来源 | 所有通知切分位置均保留消息首字节偏移；坏 CRC、序号间断、混合明密分片、未知控制位不能成为可解密结果；密文字节不得被猜作 SID/CID |
| 默认兼容与资源上限 | 默认不输出加密业务；仅放行已知业务路由；消息长度、片数、缓冲及结束清理保持有界 |
| 开始设置顺序 | `11/7` protobuf 精确为 `08 01 10 02`；未真正提交或未全部 ATT 成功，不能发空 `11/11` 查询；晚到成功不能挽回失败 |
| 状态来源边界 | 开始请求前的消息不推进；查询前开始但晚到的消息仍是 `preQueryObservation`；查询后的早回包等待全部 ATT 确认；写失败丢弃待采用状态 |
| 状态解析 | 只解释有效 `11/11`、`11/12`；字段 1/2/3 为有界 int32；保留字段编码情况；空查询回显、错误路由、重复字段、坏类型和越界值不能伪造状态 60 |
| 状态结果 | `0` 与 `10...59` 保持待完成；`60` 仅为手表报告设置完成；其他值未识别；任何结果下 `accountBinding` 都不变成成功 |
| 观察结束与生命周期 | 有效进度可继续观察；固定截止后有进度为待完成、未知状态为待分析、无本轮有效状态为超时；取消与失败保留已观测事实，旧回调不复活流程 |
| 有界观测和导出 | 查询写确认前的状态缓存最多 8 条，报告历史最多 16 条；schema 5 记录 `initialSetup / businessSessionState / businessEncrypted` 和逐命令 `serviceID / encrypted`，不包含秘密或原始载荷 |
| 界面与报告一致性 | 身份和首次设置分别展示；首次设置必须由用户点击；账号仍显示未实现；原生 JSON 导出保持可解析及快照语义 |

固定 45 秒观察计时及真实后台／断连行为还需按下方实表步骤验收。状态机测试中的受控时钟与 `timeout()` 调用，不等同真实手机定时器或蓝牙回调已经验证。

## 保留的 0.3.0 身份检查

| 检查 | 预期 |
| --- | --- |
| 身份 KDF / AES 封装 | 独立合成 nonce 与挑战向量、UInt64 回绕、NIST AES 向量、错误长度与补零拒绝 |
| RSA / AES-256 CTR | 系统 RSA-2048 公钥参数与 PKCS1 验证、完整 128 位计数器进位／回绕、前缀 16 兼容 |
| 认证 protobuf / 帧编码 | uint64 上限、重复／类型错误、未知字段有界跳过、20 字节黄金分片、CRC、FSN 回绕和资源上限 |
| 认证阶段顺序 | 请求前消息、旧首片、旧 token、回显不能推进；早回包等待所有 ATT 成功 |
| 协议分支 | 版本 1–2 不发送身份消息；3–5 按实际加密能力决定 RSA 路径；36 等待 37 |
| 最后确认 | 有效证明加最后完整 ATT 成功才完成；最终写入失败不能误报通过 |
| 能力冲突 | 前置／后置／迟到／同一通知批次内的矛盾能力在推进身份前失败 |
| 生命周期与报告 | 失败／超时／取消释放未移交秘密，晚回调不复活；逐片写入不等于整条成功；身份通过仍保留账号绑定未实现 |
| 界面和导出 | 身份边界说明与真实原生 JSON 导出保留；报告从 schema 4 扩展为 schema 5，新增字段不能把账号绑定改成成功 |

所有协议和密码测试都是合成／标准向量或受控测试对端，不包含用户实表原始载荷。它们证明实现的一致性与失败边界，不证明手表固件接受此路径。

## 0.2.1 针对性回归计划

以下场景使用独立构造的协议数据验证接收状态，不伪装为实表捕获或已完成的绑定。是否执行及通过以该版本 CI 为准。

| 场景 | 预期行为 |
| --- | --- |
| 订阅期间立即收到命令通知 | 数据当时就进入连续解析器，不等两个通知订阅都结束再开始处理 |
| 查询前半帧、查询后剩余字节 | `markQuerySubmitted()` 保留缓冲及消息来源；前置完整能力只记入 `unsolicitedCapabilities`，不算查询成功 |
| 查询前首片、查询后中／末片 | 保留首片归属及序号；不能把旧消息重新归为查询应答 |
| 完整前置能力，随后新的查询后能力 | 前者为主动诊断，后者经完整校验后才产生本次查询结果 |
| 孤立中／末片、序号跳跃或重复 | 记诊断并放弃无法完成的片段，后续新完整能力仍可处理 |
| 旧分片之后出现新首片或独立单帧 | 按确定的消息边界恢复，不因旧缓存永久卡住 |
| 无关 sid/cid、坏 CRC、无效帧头、损坏或不完整长度 | 有界重同步；无关及损坏内容不成为能力成功，后续有效消息仍可识别 |
| 目标能力字段缺失、溢出、重复、非法 protobuf 或原样查询回显 | 保持严格验证，不借容错将无效目标消息升级为成功 |
| 命令及文件通道交错通知 | 分开计数和字节数；文件数据不进入命令解析，不保存或发送文件 ACK |
| 持续主动通知超过旧版 64 次 | 在单会话 4096 次 / 256 KiB 及命令解析器 64 KiB 累计预算内继续接收；缓冲、帧和重组上限仍独立生效 |
| 帧诊断超过 32 条 | 只保留最近 32 条结构元数据，不保存原始 payload |
| 协议结果先到，ATT 成功／错误回调后到 | 在同一有效连接及正确写特征下独立记录 ATT 结果，不覆盖协议结论；拒绝旧连接回调 |

## 实体设备待验收

- 安装与签名、首次蓝牙授权、拒绝后在设置中恢复权限。
- 扫描停止与 15 秒截止、名称筛选和切换设备。
- GATT 连接、发现服务／特征、标准只读值与无值情况。
- 正在连接时取消、超时、蓝牙关闭、切换设备后迟到回调。
- 系统权限弹窗保持前台意图；真正进入后台后取消扫描和连接。
- 导出前固定状态；在文件保存界面往返时，报告内容不被后续连接状态改写。
- 协议查询仅在完整命令特征存在且标准检测结束后允许启动；先串行订阅通知，再提交已核实的 18 字节查询。
- 系统配对提示期间等待订阅（每步最多 90 秒）；每个 ATT 写确认最多 20 秒，每条逻辑命令从首片实际提交起最多等待 45 秒。
- 从首次命令通知起持续解析；提交查询仅标记归属边界，不清空已收字节或首片状态。
- 查询前完整能力保留主动来源，可用于版本选择但不被追认为查询应答。查询须完整写入后才能开始身份；冲突能力停止流程。
- 观察孤片、序号间断、坏帧及无关消息之后能否继续收到完整能力；核对各通道计数和最近 32 条结构诊断，不要求导出原始载荷。
- 在解析结束后、仍属同一连接的 ATT 回调到达时补记结果；已保存的报告保持快照语义。
- 切换设备、断连、进入后台后停止协议工作，保留已观测状态，不能接受旧连接的迟到回调。
- 验证实际版本选择的 `1/24`、`1/25` 及必要的 `1/36`、`1/37`；逐条记录全分片写入。确认身份成功后 `businessSessionState=READY`，`businessEncrypted` 与实际能力一致；版本号本身不是加密选择依据。
- 在同一前台连接点击“继续首次设置”，确认先提交 `11/7`，全部 ATT 确认后才提交空 `11/11`；检查报告中两条命令各自的服务号、加密标志及分片结果。
- 查询前主动状态和查询后状态分别保留；有早于查询写回调的完整回复时，观察是否等待整条查询确认后才采用；不得把旧状态 60 当作本轮完成。
- 从 `11/11` 首片实际提交起固定观察最多 45 秒，持续进度或重复状态不延长；状态 60 可提前结束。区分待完成、未知状态、写入失败、模式／解密失败和无有效状态超时。
- 观察结束、断连或后台后业务会话失效，已通过的身份事实和已收到的设置状态保留；再次设置须重连并重新认证，旧回调不能触发新命令。
- 跨命令及分片发送均遵守协商间隔；本版不发送 `11/6` 云成功、`11/9` 最终结束、同步完成、解绑、重置或固件命令，也不提供虚构账号资料。
- 实表验证结束后上传 **0.4.0 / build 5 / schema 5** 的完整 JSON，并说明手表点击前后画面、确认动作及能否进入主界面。`DEVICE_SETUP_FINISHED_REPORTED` 只表明手表回报状态 60，不能代替实际功能和账号绑定的独立验证。

### 已收到的实表证据

0.1.0 报告确认 GATT 保持连接及标准信息可用，发现 7 个服务、14 个特征。

0.2.0 报告进一步确认命令和文件通知均启用，共 30 次通知 / 572 字节，其中 29 次早于查询提交。查询后处理到一个通过帧长度及 CRC 检查的后续分片，但旧接收器因缺少首片而以 `UNEXPECTED_FRAGMENT` 停止；GATT 仍连接。该报告没有分通道计数或帧元数据，不能证明 29 次前置通知全是同一命令的开头，也没有完整能力应答。旧版未记录 ATT 确认，不等于已记录明确写入错误。

0.2.1 修复接收问题，0.3.0 继续实现版本 3–5 的身份握手。用户最新照片已显示 App 取得协议能力、版本为 5、传输身份已通过；手表仍在手动配对画面。照片没有对应的完整 JSON，因此不据此断言本轮采用 RSA/AES、所有中间交互已逐项核验，或账号／首次设置已完成。

0.4.0 新增的开始请求、状态查询及后续手表表现，仍待新的实表报告验收。**自动检查结果以该提交的 CI 为准；尚未执行的检查不填写通过数量，也不继承旧提交的通过结论。** 模拟器测试不能证明手表固件会接受业务请求。当前证据不足以保证完全离线激活，也不足以认定“卡在登录后就无法使用”。

## 安装产物的解释

- 模拟器 `.app` ZIP：用于兼容的 Mac/iOS 模拟器。
- 无签名设备 `.app` ZIP：仅代表设备目标构建成功，不能直接安装到 iPhone。
- 真机运行：在 Mac Xcode 中为 WatchLink 选择自己的 Team，以 Apple 开发签名构建和安装。

RFCOMM 主／数据双通道没有普通 iOS 公共 API 的直接实现。当前 BLE 路径实现了身份认证和实验性的首次设置开始／状态观察，账号绑定、完整首次设置、手机消息通知同步、健康同步和固件升级仍未实现。已启用的 GATT 特征通知与手机消息通知同步不是同一功能。编译、测试或签名通过均不改变这个范围。
