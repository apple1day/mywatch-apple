# 验证方法与边界

本项目的自动检查用于证明源码能够构建、数据处理符合约定、基础界面能够运行。它们不能证明国行一代已经与 iPhone 互通。

## 自动检查

工作流位于 `.github/workflows/ios.yml`，每次运行的实际状态和日志见 [GitHub Actions](https://github.com/apple1day/mywatch-apple/actions)。

| 检查 | 覆盖范围 |
| --- | --- |
| 工程生成与配置 | XcodeGen、Info.plist 蓝牙用途说明、目标系统、测试 target 与签名配置引用 |
| 模型测试 | 名称候选的边界、标准值合法性、会话匿名化、报告里 GATT 与原厂绑定的区分 |
| 协议编解码 | APK 请求向量、独立 CRC 校验向量、通知拆分／粘连、分片与序号、两种 CRC 字节序、非法帧／加密帧／回显／未知命令拒绝、protobuf 边界 |
| 通道识别 | 必须同时匹配命令服务、写入方向和通知属性；缺失、错误服务与重复端点不能开启查询 |
| 模拟器 UI | 原生 App 启动、首页、连接范围说明、扫描与导出入口；不执行实际蓝牙连接 |
| 模拟器截图 | 保存真实模拟器的首页截图用于布局复核 |
| 无签名设备构建 | 验证 iPhone/iPad 目标编译与链接；不使用个人证书 |

模拟器检查不把虚构设备、虚构电量或伪造 GATT 成功作为测试数据展示给用户。App 的蓝牙管理器在用户主动扫描时才初始化。

## 实体设备待验收

- 安装与签名、首次蓝牙授权、拒绝后在设置中恢复权限。
- 扫描停止与 15 秒截止、名称筛选和切换设备。
- GATT 连接、发现服务／特征、标准只读值与无值情况。
- 正在连接时取消、超时、蓝牙关闭、切换设备后迟到回调。
- 系统权限弹窗保持前台意图；真正进入后台后取消扫描和连接。
- 导出前固定状态；在文件保存界面往返时，报告内容不被后续连接状态改写。
- 协议查询仅在完整命令特征存在且标准检测结束后允许启动；先串行订阅通知，再提交已核实的 18 字节查询。
- 系统配对提示期间等待订阅（每步最多 90 秒）；命令写确认最多 20 秒、协议完整回应最多 45 秒。
- 接收早于查询的通知不能被追认为查询应答；ATT 确认与协议能力分开记录。
- 切换设备、断连、进入后台后停止协议工作，保留已观测状态，不能接受旧连接的迟到回调。
- 协议版本／能力仅作为实际观测，不据此自动发送身份认证、绑定、云成功、初始化或设备控制指令。

用户已提供 0.1.0 的实体 iPhone／一代手表报告，确认 GATT 及标准信息可用。0.2.0 的新增通知／协议查询尚需实表验收；模拟器检查不能代替这一步。

## 安装产物的解释

- 模拟器 `.app` ZIP：用于兼容的 Mac/iOS 模拟器。
- 无签名设备 `.app` ZIP：仅代表设备目标构建成功，不能直接安装到 iPhone。
- 真机运行：在 Mac Xcode 中为 WatchLink 选择自己的 Team，以 Apple 开发签名构建和安装。

RFCOMM 主／数据双通道没有普通 iOS 公共 API 的直接实现，原厂绑定、通知、健康同步和固件升级尚未实现。编译、测试或签名通过均不改变这个范围。
